Database Fundamentals

What is a Database?

A database is an organized collection of structured data stored electronically. Instead of scattering information across multiple files or spreadsheets, a database centralizes data for easy access, updates, and analysis. Common database applications include Microsoft Access, Google Forms, Airtable, and SQL databases.

🎯 Core Components of a Database

Table

A structure with rows and columns. Each column is a field (e.g., StudentID, Name), and each row is a record.

Field (Column)

A category of data (e.g., Email, Phone Number). Has a data type (text, number, date, etc.).

Record (Row)

A complete entry with values for all fields. Example: one student's full information.

Primary Key

A unique identifier for each record. No two records can have the same primary key (e.g., StudentID).

Data Type

Defines what kind of data a field holds: Text, Number, Date, Boolean (Yes/No), Currency, etc.

Query

A request to retrieve, filter, or sort data from the database (e.g., "Show all active students").

📌 Real-Life Scenario 1: School Enrollment System

Situation: A high school needs to manage 500+ student records. Previously, they used separate Excel files for each class—data was duplicated, inconsistent, and hard to update.

Solution: They create a centralized Student database with tables for Students, Classes, and Enrollments. Now:

  • ✓ Each student has ONE record (StudentID is unique)
  • ✓ Registrar can query: "Show all Grade 11 students enrolled in Physics"
  • ✓ When a student's address changes, they update it once and all records reflect the change
  • ✓ Reports are generated automatically (e.g., "Total students per course")

Designing Tables

What Makes a Good Table?

A well-designed table organizes data logically, reduces redundancy, and ensures data integrity. Each field should store only ONE type of information, and every record should be uniquely identifiable.

🎯 Table Design Best Practices

1. Define a Primary Key

Each table must have a unique identifier. For employees: EmployeeID. For products: ProductID. No duplicates allowed.

2. Choose Appropriate Data Types

Use TEXT for names, NUMBER for quantities, DATE for birth dates, CURRENCY for prices. Correct data types prevent errors and save storage.

3. Avoid Redundancy

Don't store the same info in multiple places. Example: In an Orders table, store CustomerID (not the customer's full address—that's in the Customers table).

4. Keep Field Names Clear

Use descriptive names: "DateOfBirth" not "DOB" or "db". "EmailAddress" not "email1".

5. Set Field Constraints

Mark fields as "Required" if they must always have a value. Set "Unique" if no duplicates are allowed (e.g., Email).

📌 Real-Life Scenario 2: Employee HR Database

Situation: A company with 200 employees needs to track employment records, payroll, and benefits. HR staff manually maintained Excel sheets, leading to errors and duplicate data.

Table Design:

Employees Table

• EmployeeID (Number, Primary Key)

• FirstName (Text, Required)

• LastName (Text, Required)

• Email (Text, Unique, Required)

• HireDate (Date, Required)

• DepartmentID (Number) — links to Departments table

• Salary (Currency)

Departments Table

• DepartmentID (Number, Primary Key)

• DepartmentName (Text)

• Manager (Text)

Benefits: Employee data stored once, no duplicates. Easy to query: "How many employees are in IT?" or "Show all employees hired after 2023."

Forms for Data Entry

What is a Database Form?

A form is a user-friendly interface for entering and viewing data from a table. Instead of typing directly into table rows, users fill out a form with labeled fields. Forms validate data, reduce errors, and make the database easier to use for non-technical staff.

🎯 Best Practices for Database Forms

1. Logical Field Organization

Group related fields together. Example: Group "FirstName" and "LastName" near the top, then "Address", then "Contact Info".

2. Clear Labels

Every field must have a descriptive label. Use asterisks (*) to mark required fields.

3. Input Validation

Set rules: "Email must be valid format", "Phone must be 10 digits", "Date cannot be in the future".

4. Dropdown Menus

For fields with limited options (Status: Active/Inactive, Department: IT/HR/Finance), use dropdowns to prevent typos.

5. Default Values

Pre-fill common values (e.g., Today's date, Current year). Users can still override if needed.

📌 Real-Life Scenario 3: Student Grade Entry Form

Situation: Teachers need to enter student grades for 150 students each semester. Using the raw table is tedious and error-prone.

Solution: Create a "Grade Entry Form" with:

  • ✓ Dropdown to select Course
  • ✓ Dropdown to select Student (from Students table)
  • ✓ Text field for Midterm Score (validates 0–100)
  • ✓ Text field for Final Score (validates 0–100)
  • ✓ Calculated field showing Average Grade
  • ✓ Dropdown for Letter Grade (A, B, C, D, F) — auto-populated from average
  • ✓ Save button to commit the record

Benefit: Teachers enter grades once and consistently. The form prevents invalid entries (e.g., entering 150 as a score).

Queries: Retrieving Data

What is a Query?

A query is a request to find specific data from your database. Instead of manually scrolling through thousands of records, you write a query to filter, sort, and summarize data. Queries can be simple (show all active customers) or complex (show total sales by region for Q4).

🎯 Common Query Types

1. SELECT Query (Retrieve)

"Show me all students from Grade 12" — retrieves records matching criteria.

2. FILTER Query

"Show only employees with salary > ₱50,000" — narrows results by conditions.

3. SORT Query

"List students by GPA (highest to lowest)" — orders results.

4. AGGREGATE Query

"Count how many students in each course" or "Average salary by department" — summarizes data.

5. JOIN Query

"Show student names and their course grades" — combines data from multiple tables.

📊 Query Examples (in Plain English)

Query 1: List Active Customers

"SELECT all customers WHERE Status = 'Active' ORDER BY LastName"

Shows: All active customers, sorted alphabetically by last name.

Query 2: High-Earning Employees

"SELECT EmployeeName, Salary FROM Employees WHERE Salary > 75000"

Shows: Names and salaries of employees earning more than ₱75,000.

Query 3: Count Products by Category

"SELECT Category, COUNT(*) as TotalProducts FROM Products GROUP BY Category"

Shows: How many products are in each category (e.g., Electronics: 45, Clothing: 120).

📌 Real-Life Scenario 4: Sales Tracking Database

Situation: A retail manager needs quick insights from 10,000+ sales records to make decisions.

Queries they use:

  • ✓ "Which products had zero sales last month?" → Identifies slow movers
  • ✓ "Total revenue by sales staff" → Evaluates performance
  • ✓ "Customers who spent over ₱5,000 in the last 3 months" → VIP targeting
  • ✓ "Average transaction value by day of week" → Staffing decisions

Benefit: Instead of manual calculations, the manager runs queries to get instant, accurate reports.
